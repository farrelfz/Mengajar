## 1. Executive Summary & Audit Scope

This forensic audit investigates the exact call graphs, data transformations, and literal values across all four artifact rendering pipelines:
1. **PRESENTATION** (16:9 Widescreen Slide Deck)
2. **HANDOUT** (A4 Continuous Educational Reading)
3. **WORKSHEET** (A4 Inquiry-Driven Student Activity Sheet)
4. **SCIENTIFIC_DOCUMENT** (A4 Formal Indonesian KTI Paper)

The objective is to establish the precise integration surface for connecting the Universal Design System (`app/design_system/`) into the rendering executors and engines without rewriting legacy renderers or destabilizing CSS templates.

## 2. Forensic Call Graph Analysis

### 1. Presentation Execution Path
```
PresentationBlueprint (or RenderArtifact)
  ↓ PresentationContractAdapter.adapt()
LegacyPresentationDeck
  ↓ PresentationExecutor.execute()
For each slide:
  ↓ SlideGenerator.generate_slide(PlannedSlide)
  ↓ HTML snippet generation (e.g. .hero-card, .concept-card)
  ↓ PageComposition (role=PRIMARY, block=CompositionBlock)
DocumentComposition (mode=PRESENTATION_16_9, format_id="presentation_16_9")
  ↓ MasterRenderEngine.render()
  ↓ HTMLAssembler.assemble() -> JinjaTemplateEngine("document.html")
  ↓ PlaywrightRenderer.export_pdf()
PDF Artifact
```
- **Key Interception Point**:
  - `PresentationExecutor`: Prior to `MasterRenderEngine.render()`, resolve `ResolvedRenderTheme` for `PRESENTATION` and pass it to `HTMLAssembler`.
  - `HTMLAssembler`: Injects `--ds-*` CSS custom properties generated by `HtmlDesignAdapter` into the Jinja template context.
  - `document.html`: Consumes CSS custom properties with legacy values as fallback defaults.

## 4. Architectural Findings & Strategy

1. **Compatibility-First CSS Custom Properties**:
   By exposing canonical design tokens as `--ds-*` variables at `:root` in `document.html`, existing CSS rules can bind to them with fallback defaults:
   `font-size: var(--ds-typography-presentation-title, 32pt);`
   This guarantees that if the design context is missing or disabled, legacy rendering remains 100% pixel-faithful.

2. **Integration at MasterRenderEngine & HTMLAssembler**:
   Rather than modifying individual template files or rewriting executors, `HTMLAssembler` will accept an optional `ResolvedRenderTheme` or `DesignContext`. If not provided, it deterministically resolves one based on `composition.mode` / `format_id`.

3. **ReportLab Style Factory**:
   `ReportLabRenderer` can consume a `DesignAwareStyleFactory` that translates canonical `RenderToken` values into `reportlab.lib.colors.Color` and `ParagraphStyle` rules, replacing the legacy 2013 Flat UI constants.

4. **Zero AI / Deterministic Fallback**:
   All resolutions, token lookups, and drift analyses are 100% offline, deterministic, and traceable.
