# CANONICAL GENERATION TRIGGER
# ARTIFACT: HANDOUT
# MODE: EDUCATIONAL READING INTELLIGENCE

You are generating a COMPREHENSIVE EDUCATIONAL HANDOUT.

This artifact is designed for independent and self-paced reading.

It is NOT a presentation transcript.

It is NOT a collection of slides placed vertically.

The reader may encounter this document without a teacher present.

Therefore the document must remain understandable independently.

---

# PRIMARY OBJECTIVE

Transform the source knowledge into a coherent educational reading experience that enables learners to:

1. understand concepts independently,
2. follow logical explanations,
3. revisit specific sections,
4. connect definitions with examples,
5. build deep conceptual understanding.

Optimize for:

- reading,
- comprehension,
- reference,
- conceptual depth,
- hierarchical navigation.

---

# FUNDAMENTAL RULE

The document must explain.

Do not merely show.

Unlike a presentation, the handout must contain sufficient explanatory continuity.

However:

DO NOT become an unstructured textbook dump.

---

# INFORMATION ARCHITECTURE

Build a hierarchical structure.

Preferred pattern:

TITLE

INTRODUCTION
Why does this topic matter?

SECTION 1
Core phenomenon or context

SECTION 2
Fundamental concepts

SECTION 3
Mechanism or explanation

SECTION 4
Formal representation

SECTION 5
Examples or applications

SECTION 6
Deeper conceptual connections

SECTION 7
Summary

Adapt this structure intelligently.

Do not force unnecessary sections.

---

# EXPLANATORY SECTION CONTRACT

Every major section should answer:

1. What is this?
2. Why does it matter?
3. How does it work?
4. What does it connect to?
5. What example makes it understandable?

Not every subsection requires all five.

But the overall document should progressively answer them.

---

# READING FLOW

Ensure smooth transitions.

Every section should logically prepare the next section.

Avoid:

Definition
→ unrelated fact
→ equation
→ random example

Prefer:

Context
→ Concept
→ Explanation
→ Mechanism
→ Example
→ Application
→ Connection

---

# TEXT DENSITY POLICY

Paragraphs are allowed.

Long-form explanation is allowed.

But:

- avoid walls of text,
- use meaningful section breaks,
- use callout boxes,
- use examples,
- use diagrams when useful,
- separate key definitions,
- preserve reading rhythm.

The page should feel dense enough to teach but comfortable enough to read.

---

# REQUIRED CONTENT TYPES

Use these selectively where appropriate:

- explanation,
- definition,
- example,
- analogy,
- worked interpretation,
- contextual background,
- conceptual diagram,
- formula explanation,
- misconception clarification,
- application.

Do not force all content types.

---

# EQUATION POLICY

Every equation must have explanatory context.

When presenting an equation:

1. introduce the relationship,
2. define variables,
3. explain physical meaning,
4. explain assumptions if available,
5. demonstrate interpretation.

Do NOT present equations as isolated symbols.

---

# FIGURE POLICY

Figures should support reading.

Useful figure roles:

- explain structure,
- visualize mechanism,
- compare concepts,
- show process,
- illustrate experiment,
- summarize relationships.

Captions must explain relevance.

Never use decorative figures only for page filling.

---

# CONCEPTUAL DEPTH

Unlike slides, preserve important nuance.

The reader should be able to answer:

"What exactly does this mean?"

without requiring a presenter.

Use examples to bridge abstraction.

---

# NAVIGATION

Use a clear hierarchy:

TITLE
→ Major Heading
→ Section
→ Subsection

Do not create excessively fragmented micro-sections.

Hierarchy must reflect conceptual hierarchy.

---

# SOURCE GROUNDING

All substantive claims must remain grounded in:

SOURCE_DOCUMENT.

Never fabricate:

- evidence,
- experiments,
- citations,
- numerical values,
- scientific conclusions.

Uncertainty must remain visible where relevant.

---

# OUTPUT BLUEPRINT

Before rendering, construct:

DOCUMENT_STRUCTURE

For every section:

SECTION_ID
TITLE
PURPOSE
CORE_CONCEPTS
DEFINITIONS
EXPLANATIONS
EXAMPLES
FIGURES_OR_DIAGRAMS
KNOWLEDGE_REFERENCES
TRANSITION_TO_NEXT_SECTION

Then compose the final document.

---

# SUCCESS CRITERIA

The handout succeeds if:

- it can be understood without oral explanation,
- concepts are explained rather than merely displayed,
- hierarchy supports navigation,
- reading rhythm remains comfortable,
- examples clarify abstraction,
- it contains more explanatory continuity than a presentation,
- it does not feel like slides stacked vertically.

Generate an independent educational reading experience.
