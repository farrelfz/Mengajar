# CANONICAL GENERATION TRIGGER
# ARTIFACT: PRESENTATION
# MODE: TEACHING PRESENTATION INTELLIGENCE

You are generating a TEACHING PRESENTATION.

This artifact is NOT a handout converted into slides.

Your task is to transform source knowledge into a carefully orchestrated
visual teaching experience designed for live presentation.

The presentation will be projected in a 16:9 environment and consumed
synchronously by an audience while a teacher or presenter explains the material.

---

# PRIMARY OBJECTIVE

Create a presentation that helps learners:

1. build conceptual understanding progressively,
2. maintain attention,
3. reduce unnecessary cognitive load,
4. visualize relationships between concepts,
5. experience a meaningful narrative progression,
6. understand WHY a concept matters before being overwhelmed by details.

The presentation must be optimized for:

- projection,
- visual scanning,
- live explanation,
- progressive disclosure,
- conceptual emphasis,
- narrative rhythm.

---

# FUNDAMENTAL RULE

DO NOT convert paragraphs into bullet points.

DO NOT treat slides as pages.

DO NOT attempt to place all information from the source into the presentation.

A slide deck is a SEQUENCE OF COGNITIVE MOMENTS.

Each slide must have a clear instructional purpose.

---

# REQUIRED PEDAGOGICAL NARRATIVE

Construct the presentation as an intentional cognitive journey.

Prefer a progression similar to:

HOOK
→ PHENOMENON
→ QUESTION
→ INTUITION
→ CONCEPT INTRODUCTION
→ VISUAL EXPLANATION
→ MECHANISM
→ APPLICATION
→ DEEPER CONNECTION
→ SYNTHESIS
→ REFLECTION

Do not mechanically force this sequence.

Adapt the narrative structure to the topic.

However, every major transition must have a pedagogical reason.

---

Every slide must have ONE dominant semantic role.

Allowed roles include:

- HOOK
- PHENOMENON
- QUESTION
- PROBLEM
- INTUITION
- CONCEPT
- DEFINITION
- VISUAL_EXPLANATION
- MECHANISM
- PROCESS

- CAUSE_EFFECT
- MODEL
- EQUATION
- DERIVATION
- EXAMPLE
- APPLICATION
- EXPERIMENT
- DATA_INTERPRETATION
- MISCONCEPTION
- CONNECTION
- SYNTHESIS
- REFLECTION
- SUMMARY

Avoid repeating the same semantic role excessively.

---

# COGNITIVE LOAD CONSTRAINTS

Each slide must prioritize ONE main cognitive action.

Avoid:

- multiple unrelated concepts,
- paragraph walls,
- excessive bullet lists,
- simultaneous equations and dense explanation,
- too many visual focal points.

If information is complex:

DO NOT shrink typography.

Instead:

- split conceptual stages,
- progressively reveal structure,
- simplify representation,
- use diagrams,
- isolate variables,
- distribute reasoning across multiple slides.

---

# VISUAL GRAMMAR

Choose the layout based on semantic function.

Examples:

PROCESS
→ sequential flow layout

COMPARISON
→ side-by-side structure

CAUSE_EFFECT
→ directional causal diagram

MECHANISM
→ layered explanatory visualization

EQUATION
→ equation-centered composition with visual interpretation

PHENOMENON
→ dominant image or visual observation

DATA
→ chart-first composition

CONCEPT
→ central conceptual hierarchy

MISCONCEPTION
→ contrastive before/after representation

Do NOT select layouts randomly.

Layout must encode meaning.

---

# TEXT POLICY

Slides must NOT contain:

- textbook paragraphs,
- excessive definitions,
- long explanations,
- duplicated narration.

Use text for:

- conceptual anchors,
- key relationships,
- essential definitions,
- equations,
- labels,
- short explanations.

The presenter is responsible for additional explanation.

---

# PROGRESSIVE DISCLOSURE

When a concept has multiple layers:

DO NOT show all layers simultaneously.

Prefer:

Layer 1:
What do we observe?

Layer 2:
What pattern emerges?

Layer 3:
What mechanism explains it?

Layer 4:
What formal model represents it?

Layer 5:
Where can we apply it?

---

# VISUAL PRIORITY

Prioritize visual representations whenever they improve understanding:

- diagrams,
- process flows,
- conceptual maps,
- experimental images,
- comparison structures,
- graphs,
- equations with annotations,
- spatial relationships,
- before/after transformations.

Do NOT add decorative visuals without instructional purpose.

Every visual element must serve at least one:

- explanation,
- attention direction,
- relationship encoding,
- conceptual compression,
- evidence presentation.

---

# PRESENTATION RHYTHM

Avoid monotonous sequences.

Do not generate:

TEXT
TEXT
TEXT
TEXT
TEXT

Vary cognitive and visual rhythm.

Example rhythm:

Phenomenon
→ Question
→ Diagram
→ Explanation
→ Comparison
→ Equation
→ Application
→ Reflection

But maintain narrative coherence.

Variation must never become randomness.

---

# EQUATION POLICY

When equations are used:

DO NOT present equations without conceptual grounding.

Use:

Phenomenon
→ Physical relationship
→ Variable meaning
→ Mathematical representation
→ Interpretation
→ Application

Annotate variables and relationships when useful.

---

# SOURCE GROUNDING

All concepts must originate from or be defensibly derived from:

SOURCE_DOCUMENT.

Do not fabricate:

- scientific facts,
- citations,
- experimental results,
- numerical data,
- historical claims.

If source uncertainty exists:

- simplify claim,
- mark uncertainty,
- omit unsupported detail.

---

Generate a semantic slide blueprint before rendering.

SEMANTIC_ROLE

---

# SUCCESS CRITERIA

The presentation succeeds if:

- it feels like a teaching experience,
- slides cannot simply be concatenated into a handout,
- visual structure communicates relationships,
- cognitive load is controlled,
- narrative progression is meaningful,
- each slide has a clear instructional purpose,
- typography remains projection-readable,
- no slide is merely a paragraph broken into bullets.

Generate a visually intelligent teaching presentation.

DO NOT generate a handout disguised as PowerPoint.
